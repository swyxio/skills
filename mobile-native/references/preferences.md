# Confirmed personal defaults

An explicit task or later choice overrides these defaults. General aesthetics
remain in [design-preferences](../../design-preferences/SKILL.md).

| Default | Consequence and boundary |
| --- | --- |
| Readable information density | Compact aligned rows, useful status and concise previews; reduce repetitive chrome before shrinking text or hit regions. |
| Important features upfront, secondary features progressively disclosed | Keep frequent actions visible; use familiar overflow, sheets, or named routes for rarer capabilities. Disclosure does not mean deleting capability. |
| Technical, busy mobile-user perspective | Evaluate time to inspect, decide, act, recover, and return. Keep provider diagnostics out of everyday flows. |
| Learn from established products | Use relevant Superhuman, Slack, Linear, and platform conventions, with current behavior verified before specific comparisons. |
| Framework choice per product | Retain an existing app's stack. No universal SwiftUI or cross-platform mandate for new apps. |
| Adaptive iPad layout | Follow available width; add sidebar/list-detail when simultaneous context helps. Narrow windows retain a usable compact flow. |
| Hybrid notification importance | Combine explicit rules with model assistance and discoverable user corrections/overrides. Do not treat model scoring alone as authority. |
| Respect existing lock-screen preview settings | Check OS and app configuration; do not impose generic-only or content-rich previews as a personal default. |
| Cached reading, task-driven offline actions | Add durable queued actions where the core task needs them. Define confirmation/rejection and restart behavior for those actions. |
| External entry points before content is ready | Notifications, deep links, widgets, and shortcuts show available cached context with missing new content clearly pending. Prioritize fetching the target; defer attachments and remote images. Keep the preview and Retry during delays, and recover automatically while the reader remains open. See [the opening contract](native-ux.md#opening-before-local-content-is-ready). |
| Focused verification | Physical-device checks for relevant behavior or explicit requests; report unresolved accessibility/device findings. No full hardware/audit gate for every UI edit. |
| Broad skill scope | Retain native UX, implementation pitfalls, device delivery, and playtesting; remove generic advice and duplicate policy. |

Batch cadence is deliberately **undecided**. Present rolling batches, scheduled
digests, or an in-app summary without routine pushes when the product needs a
choice. Do not silently select a personal cadence or fixed interval.

These defaults were confirmed in the skill-alignment conversation. Theme,
haptics, phone orientation, navigation count, minimum OS, AI providers, and
release policy remain product decisions; do not infer them from a single app.
